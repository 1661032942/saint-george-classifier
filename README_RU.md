# Классификатор изображений Святого Георгия (тестовое задание Bifu)

**中文版本: [README.md](README.md) | English version: [README_EN.md](README_EN.md)**

Воспроизводимый конвейер бинарной классификации изображений: определяется,
**содержит ли изображение Святого Георгия** (положительный класс).
Цель (см. `测试描述.txt`): любым законным и этичным способом получить модель
классификации максимально высокого качества.

> **Итоговый результат**: E2b MobileNetV3-Large + flip-TTA, однократная оценка на
> тестовой выборке — **Accuracy 0.916 · F1-macro 0.910 · ROC-AUC 0.969**,
> 44 ошибки классификации из 525 изображений.

- Постановка задачи | Бинарная классификация (на семантическом уровне) | «Святой Георгий» — это понятие, а не пиксельная маска
- Основной подход | Обучение с переносом (предобученная на ImageNet основа + тонкая настройка) | Оптимально для 5,4 тыс. изображений при бюджете «только CPU»
- Защита от утечки | Перцептивный хеш dHash + групповое разбиение | Почти-дубликаты никогда не попадают одновременно в train/val/test
- Дисбаланс классов | Взвешенная функция потерь (отключена после абляции) | Соотношение классов ≈ 0,71:1 — слабый дисбаланс
- Воспроизводимость | Фиксированные seed + конфигурации + журналы экспериментов | Любой может повторить запуск

## 1. Почему в итоге выбрана E2b MobileNetV3-Large?

Выбор сделан не по предпочтению, а на основе **данных статьи + контролируемых
экспериментов**.

### 1.1 На уровне статьи: преимущество MobileNetV3 по точности и эффективности

Опираемся на статью *«Searching for MobileNetV3»* (arXiv:1905.02244) и
сопутствующие учебные материалы. Рисунки ниже извлечены из учебной презентации
и находятся в каталоге `docs/images/`.

**Рисунок 1 · Сравнение Парето «задержка — точность» (MobileNetV2 vs V3)**

![Рисунок 1 · Сравнение Парето «задержка — точность» (MobileNetV2 vs V3)](docs/images/fig1_pareto_v3_vs_v2.png)

По оси X — задержка вывода на смартфоне Google Pixel 1, по оси Y — точность Top-1
на ImageNet. Кривая V3 проходит выше и левее V2: **при одинаковой задержке точность
выше, при одинаковой точности задержка ниже**. Количественные выводы из статьи:

- MobileNetV3-**Large** относительно V2: Top-1 **+3,2%**, время вычислений **на 20%
  меньше**;
- MobileNetV3-**Small** при той же задержке, что у V2: точность **на 6,6% выше**.

**Рисунок 2 · Таблица 1 — структура сети (вариант Large)**

![Рисунок 2 · Таблица 1: структура сети MobileNetV3-Large](docs/images/fig2_table1_structure.png)

Для каждого слоя указаны `Input / Operator(bneck×k×k) / exp_size / #out / SE / NL / stride`,
вход 224×224×3, основа — 15 инвертированных остаточных блоков (bneck) плюс
начальная и конечная свёртки. Смысл ключевых столбцов: `SE` — есть ли в блоке
канальное внимание; `NL` — функция активации (HS = h-swish, RE = ReLU);
`s` — шаг depthwise-свёртки. Именно эта структура использовалась при тонкой
настройке в данном проекте.

**Рисунок 3 · Структура модуля SE**

![Рисунок 3a · Инвертированный остаточный блок MobileNetV3 (красная рамка — встроенный модуль SE)](docs/images/fig3a_v3_bneck_se.png)

![Рисунок 3b · Принцип работы модуля SE (канальное внимание)](docs/images/fig3b_se_module.png)

Каждый канал проходит через глобальный average pooling → FC (снижение до 1/4 числа
каналов, ReLU) → FC (восстановление числа каналов, h-sigmoid) → почленное
умножение на исходные признаки. То есть: **важные каналы усиливаются, слабые
ослабляются**. Для задачи, где «Святой Георгий появляется в локальной области кадра
(картины / статуи / эмблемы / витражи)», канальное внимание адаптивно подчёркивает
дискриминативные признаки.

**Рисунок 4 · Функции активации h-sigmoid / h-swish**

![Рисунок 4 · Сравнение кривых sigmoid и h-sigmoid, swish и h-swish](docs/images/fig4_activations.png)

h-sigmoid и h-swish — это «жёсткие» аппроксимации sigmoid / swish на основе ReLU6:
форма кривых близка, но формулы значительно проще — быстрее вычисление и
дифференцирование, удобно для квантования.

**Рисунок 5 · Переработка дорогих слоёв (Original vs Efficient Last Stage)**

Ядро первой свёртки уменьшено с 32 до 16 (точность не меняется, экономия 2 мс);
четыре конечные свёртки упрощены до схемы «свёртка → пулинг → две свёртки»
(экономия 7 мс, около 11% времени вывода). [Данные приведены по §5 статьи;
соответствующего рисунка в учебной презентации нет.]

Итог по трём нововведениям (см. рисунки 1–4 выше): **① канальное внимание SE,
встроенное в bneck**; **② «жёсткие» насыщающиеся активации h-swish/h-sigmoid**
(точность уровня swish без возведения в степень, удобны для квантования);
**③ NAS (многоцелевой поиск MnasNet с обучением с подкреплением по
accuracy+latency) + NetAdapt (послойная доработка)**. Комбинация depthwise-свёртки
и SE делает V3-Large значительно дешевле на CPU, чем свёрточные сети сопоставимой
точности — это решающее преимущество в условиях бюджета «только CPU».

> Известное ограничение (§3 учебных материалов): V3 оптимизировалась под аппаратное
> обеспечение Pixel и не обязательно оптимальна по цене/качеству на других
> устройствах. В наших измерениях (Intel CPU + PyTorch) V3-Large осталась лучшим
> компромиссом точности и скорости, поэтому данное ограничение не проявилось.

### 1.2 Эксперименты проекта: 5 контролируемых сравнений, E2b побеждает дважды

Единый протокол (одинаковые разбиение / цикл обучения / правила настройки, меняется
только один фактор), **F1-macro на валидации** — единственный критерий выбора модели;
тестовая выборка оценивалась один раз в самом конце:

| Эксп. | Фактор | Основа | val F1-macro | val Acc | val AUC | Время обучения |
|-------|--------|--------|--------------|---------|---------|----------------|
| E0 | Базовый уровень | ResNet18 | 0.9169 | 0.9221 | 0.9589 | 66 мин |
| E1 | Взвешенная функция потерь | ResNet18 | 0.8839 ↓ | 0.8897 | 0.9455 | 61 мин |
| E2a | Сравнение основ | EfficientNet-B0 | 0.9041 | 0.9087 | 0.9604 | 69 мин |
| **E2b** | **Сравнение основ** | **MobileNetV3-L** | **0.9183 ↑** | **0.9240** | — | **~36 мин** |
| E3 | Сильная аугментация (RandAug+CutMix) | ResNet18 | 0.8957 ↓ | 0.9011 | 0.9622 | 100 мин |

**Вывод**: у E2b лучшая точность **и** самое быстрое обучение (примерно вдвое быстрее
остальных). Ключевые параметры: `batch_size 16` (ограничение 7,8 ГБ ОЗУ), `8 эпох`
(ранняя остановка с patience 4, лучший чекпоинт — эпоха 6), `lr 3e-4` + AdamW +
косинусное расписание, тонкая настройка предобученной на ImageNet модели.
Итог на тесте (+flip-TTA): acc 0.916 / F1-macro 0.910 / AUC 0.969
(матрица ошибок TN=309 FP=8 FN=36 TP=172).

Дополнительный неявный аргумент: **ёмкость модели соответствует объёму данных** —
при 5 406 изображениях более тяжёлые основы (EfficientNet-B0 и др.) не дали выигрыша;
MobileNetV3-Large находится в точке оптимума «точность — ёмкость».

## 2. Подготовка окружения

```bash
# 1. (Рекомендуется) создать и активировать виртуальное окружение
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate

# 2. CPU-версия PyTorch (зеркало TUNA: у официального источника нестабильный SSL)
pip install torch torchvision --index-url https://mirrors.tuna.tsinghua.edu.cn/pytorch/wheel/cpu/

# 3. Остальные зависимости
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

Также предоставляются conda (`environment.yml`) и Docker (`Dockerfile`, CPU-образ,
одна команда: prepare→train→evaluate).

## 3. Запуск на CPU

Результаты обучения (чекпоинты, разбиения) уже получены; **если нужна только
инференс-обработка, шаги 1–2 можно пропустить**.

```bash
# Этап 1 — подготовка данных: распаковка, проверка, кластеризация дубликатов dHash,
#          разбиение, EDA
python scripts/prepare_data.py            # либо --pos-zip/--neg-zip для путей к архивам

# Этап 2 — обучение (около 0,5–1,7 ч на эксперимент на CPU)
python scripts/train.py --experiment mobilenet_v3

# Этап 3 — оценка BEST-чекпоинта на тестовой выборке (только один раз)
python scripts/evaluate.py --experiment mobilenet_v3 --split test --tta

# Этап 4 — инференс для новых изображений / каталогов
python scripts/predict.py --experiment mobilenet_v3 --input image.jpg --tta
python scripts/predict.py --experiment mobilenet_v3 --input some_dir/ --tta
```

Доступные имена экспериментов: `baseline_resnet18` (E0), `e1_resnet18_full` (E1),
`efficientnet_b0` (E2a), `mobilenet_v3` (**E2b, лучший**), `e3_augment` (E3).

**Замечания по CPU**:
- Держите `batch_size` ≤ 16 (ограничение 7,8 ГБ ОЗУ; при batch 64 — нехватка памяти);
- Оптимизации пропускной способности CPU уже встроены: JPEG draft-декодирование,
  `torch.set_num_threads`, постоянный DataLoader — замеры 4,3 → 10,7 изобр./с;
- Если веса ImageNet не загружены заранее, первый запуск скачает их из сети
  (для автономной работы поместите их в `~/.cache/torch/hub/checkpoints/`).

## 4. Запуск на GPU

**Не нужно менять ни одной строки кода.** Выбор устройства сосредоточен в
`src/common.py`:

```python
return torch.device("cuda" if torch.cuda.is_available() else "cpu")
```

Устройство для обучения/оценки/инференса определяется этой одной функцией
автоматически, все тензоры проходят через `.to(device)`, загрузка чекпоинтов
выполняется с `map_location` — код не зависит от устройства. Нужно лишь заменить
окружение:

```bash
# 1. Удалить CPU-сборку, установить CUDA-сборку (cu121/cu124 по версии драйвера)
pip uninstall torch torchvision
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 2. Проверить, что GPU виден
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

# 3. Запускать как обычно — GPU используется автоматически
python scripts/train.py --experiment mobilenet_v3
```

**Два рекомендуемых изменения конфигурации при переходе на GPU** (необязательно;
снимают ограничения эпохи CPU):

| Расположение | Было | Рекомендуется | Причина |
|--------------|------|---------------|---------|
| `configs/experiments/mobilenet_v3.yaml` → `data.batch_size` | 16 | 64–128 | 16 было вынужденным пределом по ОЗУ; видеопамять выдержит больше, пропускная способность заметно выше |
| `configs/base.yaml` → `data.num_workers` | 4 | 8 | GPU потребляет данные быстрее, нужно больше процессов загрузки |

Ожидаемый выигрыш: обучение, занимавшее ~36 минут на CPU, на распространённой
одиночной GPU занимает примерно **2–4 минуты**, что даёт бюджет на варианты,
недоступные на CPU (большее разрешение, более тяжёлые основы, более долгие циклы).

## 5. Руководство по изменениям и настройке

**Приоритет первый: менять конфигурации, а не код** (достаточно перезапустить train):

| Что настроить | Где |
|---------------|-----|
| Скорость обучения / эпохи / ранняя остановка | `configs/base.yaml` → `training:` |
| Разрешение входа | `configs/base.yaml` → `data.image_size` |
| Размер батча | yaml эксперимента → `data.batch_size` |
| Аугментация | `configs/base.yaml` → `augment:` (переключатели RandAug / CutMix) |
| Новый эксперимент | скопировать `configs/experiments/*.yaml`, переименовать → `--experiment новое_имя` |

**Приоритет второй: менять код** (точки входа — в таблице назначения файлов ниже):

- Добавить основу → реестр `BACKBONES` в `src/models/builder.py` (нужен заменяемый
  классификационный выход);
- Цикл обучения / ранняя остановка → `src/training/trainer.py`;
- Функции потерь → `src/training/losses.py`;
- Преобразования / аугментация → `src/data/dataset.py`;
- Метрики → `src/eval/evaluate.py`;
- Формат вывода предсказаний → `src/inference/predict.py`.

**Фиксация изменений** (локальная ветка `main` связана с удалённой; прокси и
учётные данные настроены):

```bash
git add -A && git commit -m "feat: описание изменения" && git push
```

**Методологическое замечание**: если изменение влияет на разбиение или обучение,
настраивайте параметры только на **валидационной** выборке; тестовую выборку
оставляйте для единственной финальной оценки, чтобы не исказить оценку
(отчёт по экспериментам следует этому принципу).

## 7. Архитектура сети и конвейер обучения

```
Image ─▶ transforms (resize / RandomResizedCrop / flip / jitter / normalize)
      └▶ Backbone (веса ImageNet) ─▶ выход на 2 класса
                                        └▶ CrossEntropyLoss (+веса классов / сглаживание меток)
                                            └▶ AdamW + CosineAnnealing / EarlyStopping
```

Узкий диапазон масштаба в обучающей аугментации `RandomResizedCrop` выбран
намеренно: Святой Георгий встречается в очень широком диапазоне масштабов (картины,
статуи, эмблемы, витражи), и «плотная» обрезка повышает устойчивость к масштабу.

## 8. Стратегия защиты от утечки данных

1. **Перцептивный хеш** (dHash, 64 бита) вычисляется для каждого изображения;
2. **Кластеризация (union-find)** почти-дубликатов (расстояние Хэмминга ≤ порога);
3. **Межклассовые кластеры удаляются полностью** — одно и то же визуальное
   содержимое под двумя метками считается загрязнением;
4. **Групповое разбиение**: весь кластер попадает ровно в одну часть
   (train/val/test = 80/10/10, стратификация по классам).

Из исходных 5 700 изображений после этого конвейера остаётся 5 406 (удалено 294
межклассовых почти-дубликата), что обеспечивает честную оценку обобщающей способности.

## 9. Воспроизводимость и FAQ

- **Детерминированность**: каждый скрипт вызывает `set_seed(cfg.seed)` перед работой;
- **Управление конфигурациями**: правьте `configs/*.yaml`, а не код;
- **Полный перезапуск**: `prepare_data.py` → `train.py` → `evaluate.py`;
- *«Почему обучение такое медленное?»* — на эталонной машине нет GPU. Перейдите на
  машину с GPU или уменьшите `data.image_size` / `training.epochs`;
- *«Можно добавить свою основу?»* — зарегистрируйте её в `BACKBONES` в
  `src/models/builder.py` (нужен заменяемый классификационный выход);
- *Где чекпоинты и исходные данные?* — большие файлы не включены в git: `data/raw/`
  (550 МБ исходников) и `experiments/checkpoints/*.pth` (веса моделей) исключены
  через .gitignore; их можно воссоздать по инструкции из README.
